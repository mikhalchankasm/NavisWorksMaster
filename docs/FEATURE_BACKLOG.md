# Бэклог функций NavisHelper

## Кратчайшее расстояние между объектами

Статус: прототип снят с пользовательского интерфейса. Вместо него используется
предсказуемая функция высотных отметок по `Max Z` габаритного бокса.

### Как работал прототип

Пользователь выбирал один опорный объект и несколько измеряемых объектов.
NavisHelper по очереди запускал внутреннюю команду Navisworks
`MeasureShortestDistance`, преобразовывал каждое измерение в штатные redline и
сохранял все размеры в одной точке обзора.

### Почему функция отложена

- кратчайшее расстояние не является высотой и может пройти по диагонали или между
  ближайшими боковыми гранями;
- внутренний API измерений доступен только через нестабильную рефлексию;
- пакетная обработка была медленной и могла завершаться ошибкой после первого
  измерения;
- для высотных отметок нужен однозначный источник: верх объекта по габариту и
  глобальная координата Z.

### Когда стоит вернуться

Функция полезна как отдельный инструмент проверки зазоров и минимальных просветов,
но не как высотный маркировщик. Перед возвратом потребуются:

1. отдельный сценарий интерфейса «опорный объект + измеряемые объекты»;
2. проверка штатного API или устойчивой альтернативы внутренней команде;
3. пакетные живые тесты в Navisworks для всех поддерживаемых версий;
4. понятное отображение частичных ошибок и возможность повторить только
   неудачные измерения.

стабильный launcher и переключать текущую версию атомарно. Перед переключением
проверять работоспособность новой версии; при неудаче возвращаться к предыдущей.

[повторном аудите технического долга](TECHNICAL_DEBT_ROADMAP.md#11-повторный-аудит-2026-10-12-v210).

## Подтверждение доступа к документу

Статус: идея по итогам изучения AIDrafting Revit MCP.

Инструменты записи должны действовать только на документ, который пользователь
явно подтвердил в панели. Предложенный сценарий — сверка кода подтверждения и
переключатель защищённого режима. Доступ привязывается к конкретному документу.

## Идеи из блога разработчиков Autodesk по Navisworks

Статус: разобрано 2026-10-20. Источник — категория Navisworks блога
[blog.autodesk.io](https://blog.autodesk.io/category/navisworks/): 160 статей за 2012–2026 годы.
Ниже только то, чего в NavisHelper ещё нет или что меняет уже принятые решения. Каждый
приём перед использованием проверяется на Navisworks 2024–2027: статьи написаны под одну
версию.

### В ближайший релиз

- **Профиль Appearance Profiler одним вызовом** (#339). Начиная с Navisworks 2023
  встроенный плагин применяет сохранённый `.dat` профайлера:
  `Application.Plugins.ExecuteAddInPlugin("AutoAppearanceLoader.Navisworks", datPath)`
  ([статья, 2022](https://blog.autodesk.io/setting-appearance-profiler-dat-file-via-navisworks-api/)).
  Navisworks сам ищет и красит, без обхода листьев. Это прямой путь к
  `appearance_profile_apply`. Проверить заранее:
  - принимает ли плагин XML, который сохраняет профайлер;
  - как отменять такую покраску: `model_color_scheme reset` её не захватывает;
  - что получает вызывающий код при ошибке в файле.
- **Одна транзакция на пакет изменений.** `Document.BeginTransaction(name)` объединяет
  серию переопределений в один шаг отмены и откладывает внутренние уведомления
  ([статья, 2012](https://blog.autodesk.io/group-a-series-of-operations/)).
  `ModelColorSchemeService` красит по корзинам правил без транзакции. Оборачивание даст
  одну отмену Ctrl+Z на вызов и, возможно, ускорит большие порции. Измерить до и после.
- **Типы примитивов в тестах коллизий.** `ClashTest.SelectionA/B.PrimitiveTypes`
  (`Triangles | Lines | Points`) задаётся через копию теста и `TestsEditTestFromCopy`
  ([статья, 2024](https://blog.autodesk.io/setting-multiple-primitivetypes-for-clash-testing-via-navisworks-api/)).
  Нужно для моделей RVM и облаков точек, где коллизии ищутся по линиям или точкам.
  Параметр `primitiveTypesA/B` для `clash_tests_from_sets` и `clash_manage_tests`.

### В следующие релизы

- **Оси и уровни у зон коллизий и в отчётах.** `GridSystem.ClosestIntersection(point)`
  возвращает ближайшее пересечение осей с уровнем
  ([статья, 2014](https://blog.autodesk.io/closest-grid-point-intersection-to-an-object/);
  [оси и уровни, 2024](https://blog.autodesk.io/navisworks-api-working-with-grids-and-levels/)).
  Колонка «Оси / уровень» в `zones.xlsx` и в `clash_generate_report` делает место коллизии
  понятным без модели: «А-3 / +6.000» вместо координат.
- **Экспорт NWD только с видимым** (Navisworks 2026+). `Document.TryExportToNwd(path,
  new NwdExportOptions { ExcludeHiddenItems, PreventObjectPropertyExport, FileVersion,
  EmbedXrefs })`
  ([статья, 2025](https://blog.autodesk.io/navisworks-api-introducing-nwdexportoptions-in-navisworks-2026/)).
  Инструмент `export_nwd`: изолировать зону или систему и отдать подрядчику лёгкую NWD
  без лишних объектов и, по желанию, без свойств. В 2024–2025 честно отказывать.
- **Метаданные NavisHelper внутри документа.** База данных документа (`Document.Database`,
  SQL-таблицы, невидимые пользователю) хранит данные расширений прямо в NWD
  ([часть 1](https://blog.autodesk.io/document-database-part-1/),
  [часть 2](https://blog.autodesk.io/document-database-part-2/), 2013). Так снимается
  ограничение 2.14: журнал исходных цветов `model_color_scheme` теряется при перезапуске,
  и `reset` становится недоступен. Там же можно хранить идентификаторы прогонов зон
  коллизий.
- **Экспорт в FBX выбранного.** Встроенный плагин
  `NativeExportPluginAdaptor_LcFbxExporterPlugin_Export.Navisworks` экспортирует
  видимое: скрыть лишнее, вызвать, вернуть видимость
  ([статья, 2017](https://blog.autodesk.io/navisworks-api-export-model-or-model-items-to-fbx/)).
- **Гиперссылки и свои свойства у элементов.** Через COM (`InwURL2`,
  `InwOaPropertyVec`) можно записать элементам коллизии номер зоны или ссылку на замечание.
  Тогда они видны в окне свойств и в поиске
  ([гиперссылки](https://blog.autodesk.io/create-hyperlinks-for-model-objects-using-net-api/),
  [свойства, 2012](https://blog.autodesk.io/create-attributes-and-properties-for-model-objects-using-net-api/)).
  Свойства на всё поддерево придётся добавлять каждому потомку отдельно.

### Уточнения к принятым решениям

- **`InstanceGuid` есть не у всех форматов.** Стабильный GUID Navisworks строит для IFC,
  AutoCAD и Revit, но не для PDMS/RVM, CATIA и Intergraph
  ([статья, 2018](https://blog.autodesk.io/persistent-item-id-of-navisworks-objects-update/)).
  Это подтверждает решение зон коллизий не опираться на GUID. Для моделей RVM вроде 12470
  сопоставление элементов должно идти через свойства источника.
- **Снимки в цикле и перерисовка.** Экран обновляется только когда цикл сообщений UI
  доставит событие отрисовки. Долгий цикл «изменить вид → снять» показывает на экране
  старое состояние, хотя файл снимка верный
  ([статья, 2013](https://blog.autodesk.io/capture-view-image-and-force-screen-refresh-continuously/)).
  Если на снимках `clash_generate_report` появятся устаревшие цвета, лечится разбиением
  работы через `Application.Idle`.
- **Поиск Navisworks быстрее обхода.** `Search` выполняется в нативном коде, группы
  условий дают «ИЛИ» между группами и «И» внутри группы
  ([статья, 2012](https://blog.autodesk.io/search-by-or/)). Это основа для правил
  `#339` по имени узла вместо сопоставления путей в цикле по листьям.

## Идеи с форума Autodesk Navisworks

Статус: разобрано 2026-10-20. Источник — темы
[форума Navisworks](https://forums.autodesk.com/t5/navisworks-forum/bd-p/navisworks-forum-en)
с принятым решением и активностью в 2026 году: 41 тема. Большая часть — установка,
лицензии, графика и вопросы по интерфейсу. Ниже только то, что NavisHelper может
закрыть инструментом или что уточняет идеи выше.

- **Положение относительно осей.** Измерять от осей в Navisworks нельзя: оси — не
  геометрия, и предложенный обход — рисовать оси геометрией в исходной модели
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/measuring-off-grid-lines/td-p/11523482)).
  Инструмент `grid_location` для выбранных элементов возвращает ближайшее пересечение
  осей, уровень и смещения по X/Y от осей. Это та же идея `GridSystem.ClosestIntersection`,
  что и подписи осей у зон коллизий (раздел выше). Важное ограничение: оси и уровни в
  Navisworks есть только у моделей Revit
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/grids-and-levels-are-greyed-out/td-p/11803473)).
  Для IFC, DWG и RVM инструмент честно сообщает, что осей нет.
- **Комментарии к коллизиям.** В интерфейсе их почти не видно: только последний
  комментарий в окне точки обзора, остальные открываются через панель комментариев
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/clash-comments/td-p/8685378)).
  `clash_set_status` уже умеет добавлять комментарий. Не хватает чтения: показать все
  комментарии результата или группы и выгрузить их в отчёт или книгу зон.
- **Проверка «здоровья» сцены.** Скорость перемещения внезапно становится километры в
  секунду, а модель пропадает при вращении. Причина — автоматические плоскости отсечения:
  они пересчитываются по габаритам при каждом добавлении модели
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/walk-speed-and-odd-navis-behavior/td-p/7605910)).
  Тот же корень у мусора RVM с точечными габаритами за километры от площадки (сессия
  покраски 12470). Инструмент только для чтения находит элементы с габаритами далеко за
  пределами основной массы, режим отсечения и единицы моделей, а дальше предлагает
  скрыть выбросы или зафиксировать отсечение.
- **Прозрачность по свойству без смены цвета** нужна и другим. Пример — сделать
  прозрачными зоны обслуживания оборудования через Appearance Profiler по свойству
  `Material = Clearance`
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/selecting-equipment-clearances-separately-in-navisworks-models/td-p/13833313)).
  Правило только с прозрачностью и правилами по свойствам вышло в #339; сценарий стоит
  показать в руководстве.
- **Внешние таблицы как свойства.** DataTools связывает Excel или базу данных со
  свойствами через SQL, и ODBC-драйвер Excel капризен к функциям
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/data-tool-mit-sql-abfrage-auf-bestimmte-zeichen-reduzieren/td-p/14091359)).
  Инструмент `properties_import_table`: CSV/XLSX с ключевой колонкой → пользовательская
  вкладка свойств у найденных элементов, с пробным прогоном. Вместе с идеей своих
  свойств через COM (раздел выше).
- **Запуск выбранных тестов коллизий** в интерфейсе появится только в 2027
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/clash-detective-tab-run-specific-tests/td-p/13984272)).
  `clash_run_batch` уже делает это для 2024–2026. Стоит сказать об этом в руководстве.
- **Горячие клавиши для «Скрыть невыбранное» и похожих команд** в Navisworks нет, их
  правят в XML
  ([тема](https://forums.autodesk.com/t5/navisworks-forum/hide-unselected-looking-for-the-keyboard-shortcut/td-p/13956586)).
  Панель NavisHelper уже ловит свои сочетания на потоке Navisworks (#311), можно добавить
  частые команды просмотра.
