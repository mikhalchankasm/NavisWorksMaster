# Три сценария NavisHelper

Скажите агенту, какой результат нужен. Он использует локальный MCP, показывает
план изменений и проверяет результат в Navisworks. Ниже — последовательности
для существующих инструментов; реальные изображения демонстрации готовятся в
[NW-05 на доске проекта](https://github.com/users/mikhalchankasm/projects/3).

Перед началом откройте модель в Navisworks с NavisHelper и проверьте
[подключение MCP](NAVISWORKS_MCP_QUICKSTART.md). Агент вызывает
`list_navisworks_hosts`, выбирает нужное окно, проверяет `mcp_health_check` и
`active_model_context`, затем сохраняет `instanceId` для всех адресных вызовов.
При смене документа результаты разных моделей не объединяются.

| Хочу получить | Профиль MCP | Что изменится |
|---|---|---|
| Найденный файл модели в текущем виде | `core` | Выделение и камера |
| Обзор сохранённых коллизий и HTML-отчёт | `core,clash` | При создании отчёта: вид, сохранённые точки и файлы |
| Сохранённый вид узла с секущим боксом | `core,sections` | Вид и сохранённые точки документа |

Профиль задаётся при запуске сервера: [настройка и проверка](MCP_CLIENT_GUIDE.md#configure-and-verify-a-profile).
Read-only подходит для чтения данных; команды изменения выделения, вида и
записи отчёта в этом режиме недоступны, включая их preview.

## 1. Найти и показать файл модели

> «Найди подключённый файл HVAC-DEMO.ifc, выбери его и приблизь вид».

Имя условное: подставьте имя из открытой модели. Агент проверяет доступные
корни через `list_root_items` с `limit=50`, затем вызывает
`find_root_items_by_name` с `names=["HVAC-DEMO.ifc"]`, `comparison="equals"`
и `previewLimit=10`. Если точного совпадения нет, он показывает возвращённые
подсказки и не расширяет поиск молча.

Полученные `matchHandles` передаются в `select_items`; затем
`selected_items_preview` с `limit=20` подтверждает состав выделения,
а `zoom_to_selection` приближает камеру. Эти две команды изменения выделения
и камеры выполняются сразу, без параметра `apply`.

**Проверяемый результат:** нужный корневой файл выбран и виден в окне; агент
сообщает фактическое число выбранных элементов. Совпадение нескольких корней
показывается как неоднозначность, а не как один найденный файл. Handles
действуют только в текущем сеансе и документе; после их истечения нужен новый
поиск. Для поиска по свойствам вместо имени файла используется `find_items`.

## 2. Проверить коллизии и создать небольшой отчёт

> «Проверь сохранённые New и Active в HVAC vs Structure. Покажи план отчёта
> по первым трём результатам и создай его в новой папке NavisHelperDemo».

Нужен Navisworks Manage с уже рассчитанными, непустыми результатами теста.
Агент читает `clash_list_tests` с `limit=50`, затем `clash_list_results` с
точным возвращённым `testName`, `statusFilters=["New","Active"]` и `limit=3`.
Он проверяет, что имя относится ровно к одному тесту. Если подходящих
результатов нет, сообщает об этом; этот сценарий не запускает расчёт коллизий.

`clash_generate_report` сначала вызывается с `apply=false`, теми же тестом,
статусами и `limit=3`, `runTests=false`, `overwrite=false` и явным
`outputDirectory` — полным путём к новой папке. Агент проверяет объём и пути
preview, затем при разрешённой записи повторяет с `apply=true`. Он отслеживает
`clash_report_status`, если операция ещё выполняется, и проверяет итоговые
ошибки, предупреждения, пути к HTML и снимкам, а также созданные viewpoints.

**Проверяемый результат:** доступный HTML-отчёт по фактически обработанным
результатам и созданные сохранённые виды; наличие снимков подтверждается
отдельно. Это ограниченная выборка, не полный аудит модели. Учитываются
флаги продолжения и пропуски, а сохранённые результаты отражают последний
расчёт теста. Для обзора без записи доступен MCP prompt `review_clashes`:
[порядок чтения](MCP_CLIENT_GUIDE.md#workflow-prompts).

## 3. Сохранить вид выбранного узла с секущим боксом

> «Создай для текущего выделения вид DEMO — Section Box с запасом 500 мм
> и красной мишенью, затем покажи его».

Агент проверяет `selection_status` и `selected_items_preview` с `limit=20`.
При пустом выделении останавливается. Для `section_box_viewpoint` задаёт
`name="DEMO - Section Box"`, `folderPath="NavisHelper Demo"`,
`boxOffsetMm=500`, `markStyle="target"`, `targetCrosshair=true`,
`overwrite=false` и сначала `apply=false`. После проверки запланированных
видов повторяет с `apply=true` в пределах запроса пользователя.

Через `list_saved_viewpoints` агент находит созданный вид и активирует его
точным путём с `activate_saved_viewpoint`: preview, затем apply. Проверяет
`get_current_section_box` и вид в окне. При совпадении имён не выбирает
произвольный результат и не включает перезапись автоматически.

**Проверяемый результат:** сохранённая точка с включённым section box и
маркером вокруг выбранного узла. Секущий бокс ограничивает видимую область;
сценарий не подменяет его скрытием объектов. Сохранение самого NWD/NWF на
диск — отдельное действие. Для изображения можно дополнительно запросить
`capture_current_view` с явным путём: preview, затем apply.

При таймауте записи агент проверяет `last_operation_status` и
`mcp_recent_calls`, а не повторяет изменение вслепую. Точные поля и ограничения:
[контракты инструментов](MCP_TOOL_CONTRACTS.md); границы локального доступа и
облачного AI: [безопасность и совместимость](SECURITY_AND_COMPATIBILITY.md).
