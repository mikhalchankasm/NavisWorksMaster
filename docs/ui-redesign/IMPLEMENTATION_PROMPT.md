# Промт: реализация редизайна UI панели NavisHelper

Ты — инженер по C#/WPF, работаешь в репозитории **NavisHelper** (плагин для Autodesk Navisworks Manage 2024/2025/2026/2027, .NET Framework 4.8.1, x64). Тебе нужно реализовать редизайн боковой панели плагина согласно утверждённому макету. Код UI почти целиком в одном файле:

> `NavisHelper/WPF/NavisHelperPanel.cs` (~6450 строк, программно строит весь UI; XAML для панели нет).

**Перед началом обязательно прочитай:** `CLAUDE.md`, `BUILD_BUNDLE_RULES.md`, `AGENTS.md` (раздел про read-only review wrapper).

## Утверждённый макет (источник истины по внешнему виду)
Открой в браузере и сверяйся пиксельно:
> `docs/ui-redesign/NavisHelper_UI_redesign.html`

Это интерактивный превью всех вкладок. Твоя задача — привести реальную WPF-панель к этому виду. Где WPF не позволяет повторить 1:1 — приоритет у функциональности и аккуратной группировки, а не у точных цветов CSS.

## Жёсткие правила (НЕ нарушать)
1. **Это рефакторинг UI, а не логики.** Не меняй поведение существующих команд, обработчиков, плагинов. Перемещаешь/перегруппировываешь кнопки и контейнеры — да; переписываешь бизнес-логику (например медленный `InvertSelection`) — **нет** (это отдельная задача владельца).
2. **`NavisHelper.csproj` — НЕ SDK-style.** Любой новый `.cs` файл нужно явно добавить `<Compile Include="ИмяФайла.cs" />`. Без этого он не скомпилируется.
3. **Не ломай командную палитру.** Все вызовы `RegisterPaletteCommand(...)` (строки ~366-401) должны продолжать указывать на существующие методы. Если убираешь UI-кнопку — соответствующую команду палитры либо оставь, либо удали осознанно (см. раздел про слоты).
4. **Не трогай функциональность вкладки «Коллизии»** — только её компоновку (resizable таблицы + сворачиваемые настройки, см. ниже). Все обработчики (`RunAllClashTests`, `PreviewSelectedClash`, грид-биндинги, контекстные меню, GIF и т.д.) должны работать как раньше.
5. **После сборки** разложи DLL по бандлу для версий **2024, 2025, 2026, 2027** согласно `BUILD_BUNDLE_RULES.md` (конфигурации `Release2024/2025/2026/2027` копируют DLL в `NavisHelper.bundle/Contents/<версия>/`).
6. UI и тексты — **на русском** (как сейчас).

## Доступные хелперы (используй их, не плоди дубли)
- `Btn(iconName, fallbackEmoji, text, tooltip, pluginId)` — кнопка запуска плагина (полная ширина).
- `NavBtn(iconName, fallbackEmoji, text, hotkey, tooltip, Action)` — кнопка навигации по дереву.
- `ActionBtn(iconName, fallbackEmoji, text, tooltip, Action, width=0)` — кнопка-действие.
- `CreateGroupHeader(text)` — заголовок группы.
- `CreateSeparator()` — горизонтальный разделитель.
- `WrapInTab(header, content)` — оборачивает контент в `TabItem` со `ScrollViewer`.
- `MakeButtonContent(iconName, emoji, text)` — контент кнопки (иконка+текст).

Порядок вкладок задаётся в конструкторе (строки ~254-259):
```
CreateNavigationTab(); CreateToolsTab(); CreateAIColorsTab();
CreateViewpointsTab(); CreateClashTab(); CreateImportExportTab();
```
Порядок и состав из 6 вкладок сохраняем: **🌳 Выделение · 🎨 Цвета · 🤖 AI · 📷 Виды · ⚠ Коллизии · 📦 Данные**.

## Задача 1 — Вкладка «🌳 Выделение» (`CreateNavigationTab`, ~930-1007)

**1a. Память выборки: 10 кнопок → 1 ячейка.**
Сейчас два цикла `for (i=1..5)` создают `Save S1..S5` (строки ~944-961) и `Recall 1..5` (~963-980). Замени оба на одну группу `CreateGroupHeader("Запомнить выборку")` с двумя кнопками в одной строке:
- `ActionBtn(... "Запомнить" ..., () => SaveSelectionSetSlot(0))`
- `ActionBtn(... "Вернуть" ..., () => RecallSelectionSetSlot(0))`
- Под ними — `TextBlock`-индикатор «в памяти: N объектов» (обновляй из `SaveSelectionSetSlot`/`RecallSelectionSetSlot`; если слот пуст — «память пуста», серым).

Бэкенд `_selectionSlots` (массив `ModelItemCollection[5]`) можно оставить как есть — UI просто использует индекс 0.

**1b. Хоткеи слотов.** В `OnGlobalKeyPressed` (switch по `Key.D1..D5/NumPad1..5`, ~326-345) оставь рабочими только `Ctrl+1` (Recall slot 0) и `Ctrl+Shift+1` (Save slot 0). Кейсы D2..D5/NumPad2..5 удали (или оставь, но в UI и подсказке не упоминай). В блоке подсказки на вкладке покажи только `Ctrl+1` / `Ctrl+Shift+1`.

**1c. Палитра.** Команды `Save Slot 2..5` / `Recall Slot 2..5` (строки ~393-396, 398-401) удали. Оставь по одной: `Save Slot` и `Recall Slot` (slot 0). Переименуй для ясности в «Запомнить выборку» / «Вернуть выборку».

**1d. Перегруппировка кнопок (по макету):**
- Группа **«Навигация по дереву»**: строка 1 — `Parent` / `Child` / `Sibling`; строка 2 — `Leaf` / `All Under`.
- Группа **«Операции с выборкой»**: `Invert` / `Isolate` / `Unhide All` (строка), `Select by Property` (строка), `Копировать имена` / `Filter by list` (строка). Сейчас `Копировать имена` и `Filter by list` висят отдельными `Btn(...)` после блока подсказки (строки ~1003-1004) — перенеси их в эту группу.
- Группа **«Запомнить выборку»** (см. 1a).
- Блок подсказки горячих клавиш — компактный, внизу вкладки.

## Задача 2 — Вкладка «🎨 Цвета»: Match Color + ручной ввод цвета

Файл: метод `CreateMatchColorSection()` (~2229-2261). Сейчас там: кнопки `Считать`/`Применить`, свотч `_matchColorSwatch`, `_matchColorText`, чекбокс «Применить прозрачность».

**2a. Добавь поле ручного ввода цвета** (HEX / RGB / RAL):
- `TextBlock`-подпись «Цвет вручную (HEX / RGB / RAL):».
- `TextBox` (новое поле, заведи приватное поле `_manualColorBox`) + рядом кнопка `Считать`. Placeholder-подсказка: `#B11A1A · 177,26,26 · RAL 3000`.
- Кнопка **«Считать»** рядом с полем НЕ применяет цвет, а только **разбирает** введённое значение в текущий цвет: парсит через `ColorParser.ParseColor(...)`, затем — как в `OnPickColor` (строки ~1447-1455) — заполняет `_matchColorRgb`, `_matchColorSwatch.Background`, `_matchColorText`. При ошибке парсинга — `SetGlobalStatus("Не удалось разобрать цвет: ...", Brushes.DarkRed)` и не менять свотч.
- Существующую кнопку чтения с объекта (`OnPickColor`) оставь, но переименуй ярлык в **«С объекта»** (логика та же — пипетка с первого выделенного).
- Кнопка **«Применить»** (`OnPasteColor`) — единственная, что красит выборку. Не трогать.

**2b. Расширь `ColorParser` под RAL.** Файл `NavisHelper/Core/ColorParser.cs` сейчас понимает `#AARRGGBB`, `#RRGGBB`, `R,G,B`. Добавь поддержку RAL Classic:
- Создай `NavisHelper/Core/RalColors.cs` со `static Dictionary<string,(byte R,byte G,byte B)>` для палитры **RAL Classic** (полный набор ~213 кодов; ключи — строки кодов вида `"3000"`). **Добавь файл в `.csproj` через `<Compile Include="Core\RalColors.cs" />`.**
- В `ColorParser.ParseColor` добавь ветку: если строка начинается с `RAL` (без учёта регистра) — отбрось префикс/пробелы и найди код в таблице; либо если трим-строка без `#` и без запятых целиком совпадает с известным RAL-кодом — тоже трактуй как RAL. Иначе — текущая логика (HEX/RGB). При неизвестном RAL — `ArgumentException` с понятным сообщением.
- Порядок проверки: `#` → HEX; `RAL`/совпадение с кодом → RAL; иначе → RGB по запятым.

**2c. Группировка вкладки «Цвета»** приведи к макету: группы **Окраска** (`Colors By Name` на всю ширину; `Color by Property` / `Override PDMS` в строку; `Сбросить все overrides` отдельной «тихой» кнопкой) → **Match Color** → **Перенос цветов** → **История покрасок**. Состав кнопок не меняется, только компоновка/заголовки.
