# NavisHelper — редизайн вкладок документа

## Цель

Сделать панель NavisHelper быстрее в использовании и понятнее для частых сценариев:

- снизить визуальный хаос;
- уменьшить количество переключений между вкладками;
- явно разделить функции по типам задач;
- подготовить базу для безопасного расширения без ломки текущей архитектуры.

В этой версии меняется **только UI-расположение**. Основной код плагинов остаётся прежним, переезд выполняется перестановкой `Btn(...)` в `NavisHelperPanel.cs`.

---

## 1) Что ломает текущую UX

| Проблема | Где выражается | Почему это мешает |
|---|---|---|
| Перегруженная вкладка | 9 вкладок в общей сложности, высокая разнородность | Усложняет поиск: соседние задачи в одной вкладке не связаны по смыслу |
| Ложные темы | Вкладки с одним контролом или с перемешанными функциями | Возникает вопрос «где найти функцию» вместо «что сделать» |
| Дублирование Section Box | Есть в 2–3 местах | Одна и та же функция выглядит как разные инструменты |
| Match Color в AI | Цветовая операция лежит в AI-вкладке | Пользователь не ассоциирует пипетку с AI-сервисом |
| Перенос цветов отдельно от окраски | Цветовые команды разбросаны | Ключевая модель «выбрал, перекрасил, сохранил/восстановил» нарушена |
| Слабая discoverability | Нет единого статуса и быстрого поиска команд | Пользователь начинает «тыкать всё подряд» |

## 2) Целевая структура вкладок

Новая структура: **6 основных вкладок + компактное меню**.

1. `🎨 Цвета`
2. `🤖 AI`
3. `🌳 Выделение`
4. `📷 Виды и разметка`
5. `⚠ Коллизии`
6. `📦 Данные`

Дополнительно: меню `⋯` (Dev/About/настройки) в правом верхнем углу дока.

## 3) Детализация вкладок

### 3.1 `🎨 Цвета`

#### Что уходит сюда

- `Colors By Name`
- `Override PDMS Colors`
- `Match Color` (чтение/применение цвета)
- `Перенос цветов` (папка + экспорт/импорт)
- история окрасок (переносим из AI)

#### Предлагаемый макет

```
Быстрая окраска
  [Colors By Name] [Override PDMS] [Random colors]* [Color by Property]*
Match Color
  [Считать] [Схема превью] [Применить] [Прозрачность: 25%]
Перенос цветов
  Папка [ ... ] [Выбрать]   [Выгрузить] [Загрузить]   [Перезаписывать]
История
  [10 последних] [Выделить] [Применить выбранное]
```

`*` — новые кнопки (опционально в v1).

#### UX-решение
- Главный акцент на сценарий «как покрасить выделение».
- `Match Color` и история рядом с ручной окраской, а не в AI.
- Блоки с минимально меняющейся логикой должны быть всегда видны без скролла.

### 3.2 `🤖 AI`

#### Что остаётся здесь

- Выбор модели/ключа
- выбор схемы
- запуск AI-применения
- лог ответа модели

#### Предлагаемый макет

```
Модель: [openrouter/...]
Thinking: [x]
Цветовая схема (1..10)  [переключатель/превью]
[Применить AI-окраску]   ← sticky
Лог ответа: [Копировать] [Сохранить]
```

#### UX-решение
- Вкладка строго AI-сценариев.
- Закреплённая кнопка действия уменьшает «потерю» основного CTA при длинной прокрутке.

### 3.3 `🌳 Выделение`

#### Что уходит сюда

- `Parent`, `Child`, `Sibling`, `Leaf`, `AllUnder`
- `Invert Selection`
- `Copy names`
- `Filter by list`
- выбор сохранённых выделений (слоты 1..5)

#### Предлагаемый макет

```
Дерево
  [Parent] [Child] [Sibling] [Leaf] [AllUnder]
Список выделения
  [Инвертировать] [Isolate] [Unhide All]  [Сохранить] [Recall]
Работа со списком
  [Копировать имена] [Фильтр по списку]
```

#### UX-решение
- Функции, которые работают с выделением, собраны в одну вкладку.
- Кнопки `Isolate/Unhide` логично соседствуют со сценариями инспекции модели.

### 3.4 `📷 Виды и разметка`

#### Что уходит сюда

- `Markup Viewpoint` (`Пометить выделенное`)
- `Top View + Section`
- `Bounding Rect`
- `Sort Viewpoints`
- `Section Box по выделению`
- `Сохранение точек обзора` (из импорта/экспорта)

#### Предлагаемый макет

```
Точки обзора и разметка
  [Пометить выделенное] [Вид сверху + сечение] [Габаритный прямоугольник]
  [Виды по 6 сторонам]
Section Box
  [Section Box] [Переключить] [Сброс]
  Отступ, мм: [----•----] [Прозрачность: авто]
  [Прозрачность бокса] [Прозрачность по уровню]
Viewpoints
  [Сортировать] [Сохранить список VP] [Анимация по VP]
```

#### UX-решение
- Все команды с камерой и разметкой в одном месте.
- Вставка «анимации» и «6 сторон» как расширения текущего инструмента обзора.

### 3.5 `⚠ Коллизии`

#### Что остаётся
- Полный модуль коллизий без структурных изменений.

#### Небольшие улучшения в рамках редизайна
- Вывести поле `px` рядом с кнопкой маркера как стандартный элемент управления, без костыльного `Insert(... - 1)`.
- Сохранить текущие sticky-кнопки и фильтры.

### 3.6 `📦 Данные`

#### Что уходит сюда

- `CSV → атрибуты`
- `Импорт PS-листов`
- `Сохранить иерархию`
- `Сохранить как NWD 2018`
- `Export selected properties to Excel` (новая опция)

#### Предлагаемый макет

```
Импорт
  [CSV → атрибуты] [Импорт PS-листов]
Экспорт
  [Сохранить иерархию] [Сохранить как NWD 2018] [Экспорт свойств в Excel]
```

#### UX-решение
- Жёстко разделяем «внести в модель» и «вынести из модели».

### 3.7 Доп. меню `⋯`

Вместо отдельных вкладок:

- `Dev`: загрузка DLL (как сейчас)
- `Открыть лог`
- `Настройки AI`
- `О программе`

Если делаем минимальный редизайн — оставляем отдельные вкладки `⚙ Настройки` и `ℹ`, но основной вариант — единый popup.

## 4) Глобальные улучшения

### 4.1 Общий статус-бар

Нижняя полоса для всего дока:

- `выделено: 12`
- `последнее действие: AI-окраска (12 эл., 3 группы)`

Заменяет три разрозненных статуса (`_selStatus`, `_clashStatus`, `_devStatus`) и снижает визуальный шум.

### 4.2 Поиск команд (Cmd/Ctrl + P)

Открытие палитры с поиском по имени/tooltip кнопок:

- меньше переключений вкладок;
- доступ к 20+ действий за 1–2 ввода;
- особенно полезно на пульте с плотным UI.

### 4.3 Sticky-action для ключевых вкладок

- `🎨 Цвета`: базовая кнопка окраски закреплена внизу.
- `📷 Виды и разметка`: закрепить «Применить текущий сценарий разметки».
- `⚠ Коллизии`: оставить существующую модель sticky-кнопок.

### 4.4 Иконки вместо emoji

Иконки уже поддерживаются через `icons/` и `LoadIcon()`. Для кнопок заменить emoji fallback на PNG (16/20 px), чтобы:

- унифицировать стиль;
- убрать зависимость от платформенного рендера emoji;
- сделать интерфейс более “продуктовый”.

## 6) Команды, которые стоит добавить в 1–2 релиза

### В рамках вкладки `🎨 Цвета`
- `Color by Property` — автоокраска по значению свойства.
- `Random colors` — уникальный цвет для каждого значения.
- `Save/Restore color preset` — экспорт/импорт пресета всей модели.
- `Reset all overrides` — глобальный сброс.

### В рамках вкладки `🌳 Выделение`
- `Invert Selection`
- `Isolate Selection` / `Unhide All`
- `Select by Property Value`
- `Selection sets` в слоты `Ctrl+1..5`

### В рамках вкладки `📷 Виды и разметка`
- `Markup с текстовой выноской` (не только эллипс)
- `Виды по 6 сторонам` (front/back/left/right/top/bottom)
- `Анимация по выбранным точкам обзора`

### В рамках вкладки `⚠ Коллизии`
- `Assign to` для `ClashResult`
- `BCF экспорт` выбранных коллизий
- `Комментарий в выделение` из контекста коллизии

### Сквозные
- Command Palette (`Ctrl+P`)
- `Recent files` для последних `.txt`/`.csv`

## 9) Критерии готовности (DoD)

- Количество основных вкладок: 6.
- Каждая команда из текущего набора найдена в новой вкладке ≤ 2 клика.
- Нет более одного «источника истины» для `Section Box`.
- Сценарии `окраска`, `выделение`, `вид` выполняются без переключения в вкладки AI/Dev/About.
- Нет изменений в внешнем API и `.addin` плагинах для первого этапа.
- Документ обновлён и согласован с бизнес-приоритетом.
