# NavisHelper 2.10.0.0

Минорный, а не патч: добавлены четыре MCP-инструмента и **ни один не удалён**, поверхность
выросла со 100 до 104 без поломки вызывающих. 43 изменения со времён 2.9.0.0.

## Основные изменения

### Новые инструменты

- `clash_tests_export` и `clash_batchtest_import` — перенос Clash-тестов между документами.
- `get_current_section_box` и `isolate_by_box` — чтение текущего Section Box и изоляция по
  координатной зоне, с guarded replay в библиотеке сценариев.

### Идентичность вместо имени: сквозная серия исправлений

Один класс дефектов проходил через весь продукт — **имя подменяло идентичность**. Путь из
отображаемых имён не содержит индекса среди сиблингов, поэтому два разных объекта с
одинаковым именем сливались в один; имя файла документа не содержит каталога, поэтому две
модели `model.nwd` в разных папках были неразличимы. Исправлено по всем найденным местам:

- `find_items`, `select_items`, `find_items_by_bbox` и остальные точки дедупликации теперь
  ключуются по идентичности элемента, а не по пути — до этого счётчики занижали результат;
- сборщики видимости — там же и по той же причине;
- `scopeNodePath` принимает ровно тот путь, который печатают все инструменты, а печатный
  путь, адресующий два узла, **отклоняется** вместо выбора одного из них наугад;
- `start_navisworks` больше не отвечает хостом, подобранным по имени файла. Прямой ответ
  даёт только pid, который этот вызов запустил; любой другой кандидат подтверждается полным
  путём через `host_status`, как это делает путь аттача.

### Скорость

- **Аттач вместо запуска.** Запрос файла, уже открытого в готовом хосте, присоединяется к
  нему: измерено **66–173 мс** против примерно **15 500 мс** на запуск нового экземпляра.
- **`select_by_search` со scope** стоит своего ответа, а не своей области.
- **`find_items_by_bbox` пропускает целые модели**, которые не могут содержать совпадение,
  до того как их элементы попадут в счётчик `maxScannedItems`. Запрос вне габаритов модели
  стоит **32 мс** вместо 10 135; фильтр по исходному файлу без совпадений — **19 мс**.
- Брошенный обход `find_items` освобождается и больше не замедляет сессию.
- Сокращён per-request манифест MCP.

### Отказы, которые объясняют себя

- Условие поиска без категории в whole_model **отклоняется** вместо ответа «0 совпадений».
- Ошибка scope в clash-инструментах называет параметры, которые принимает именно этот
  инструмент.
- Обрезанный обход bbox говорит, что помогает на самом деле, а не что попало.
- `last_operation_status` отвечает без request id.

### Измерения

Базовая линия задержек: **99 из 104** инструментов несут измеренное число, остальные 5
названы с причиной. Четыре окна на живом Navisworks. Медленных инструментов ровно три:
`select_by_search` (333 мс), `isolate_by_box` (2 500–9 590 мс, бимодальный) и
`model_color_scheme` (2 879–3 069 мс); остальные — десятки миллисекунд.

### Guard'ы против гниения документации и сборки

Девять проверок в CI, каждая со своим самотестом: инвентарь компиляции, каталог MCP,
типизированный роутер хост-команд, локализация панели, поверхность инструкций агента,
задокументированность флагов усечения, **согласованность версии продукта**, арифметика
покрытия базовой линии и дрейф установленного bundle.

## Ограничения и требования

- Для framework-dependent `NavisHelper.AiWorker` и MCP-сервера требуется установленный
  .NET 9 Runtime.
- Установщик не подписан Authenticode; Windows может показать предупреждение издателя.
- Autodesk Interop не включается в дистрибутив и загружается из установленной копии
  Navisworks.

### Что НЕ проверялось, и это заявляется прямо

- **Компиляция Inno Setup не выполнялась**: Inno Setup на машине выпуска не установлен.
  Скрипт `installer/NavisHelper.iss` обновлён до `2.10.0.0`, но установщик не собирался.
- **Runtime smoke только на Navisworks Manage 2027.** Сборки 2024, 2025 и 2026 проходят
  build-validation; отдельный живой прогон на них не заявляется.
- **Публичный installer не скачивался и не сверялся по SHA-256** — на момент этих проверок
  ассет не опубликован.
- **Частичное отсечение bbox по нескольким присоединённым файлам не проверено.** Оба
  документа, на которых оно измерялось, имеют `modelCount: 1`. Нужен NWF с несколькими
  файлами.
- **Синхронный `dump_subtree_names` не измерен на успешном пути**: лимит 5000 элементов, и
  все корни обеих использованных моделей его превышают. Измерен только отказ (504–600 мс).

## Известное поведение, о котором стоит знать до вызова

- `selection_color_by_property` пишет **permanent** наложения цвета, и **отката у него нет**
  через MCP: `model_color_scheme operation=reset` их не отменяет — проверено, после окраски
  44 элементов reset ответил `reset: false`. Единственный путь назад — закрыть документ без
  сохранения.
- `model_color_scheme` по умолчанию **очищает выборку** после apply
  (`clearSelectionAfterApply`), поэтому selection-инструмент, вызванный сразу после,
  работает по пустой выборке.
- `navishelper_timing.status` — вердикт транспорта, а не инструмента: структурный отказ
  приходит со `status: "ok"` и `ok: false` в payload.
