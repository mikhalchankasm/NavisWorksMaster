# NavisHelper 2.17.0.0

Обновление после [2.16.0.0](https://github.com/mikhalchankasm/NavisWorksMaster/releases/tag/v2.16.0.0). Главное:
- **выделение:** `select_items` снимает выделение, `hide_selected` его сохраняет, снимок вида можно сделать без подсветки;
- **пути к узлам RVM:** путь через `/` находит узлы, чьи имена начинаются с `/`;
- **большие ответы по страницам:** `selected_items_tree` листается, `active_model_context` умеет отдавать только имена корней.

Новых MCP-инструментов нет, их по-прежнему **118**; у существующих появились параметры.

## Какой файл скачать

| Файл | Кому нужен |
| --- | --- |
| **`NavisHelperSetup-2.17.0.0.exe`** | **Всем, начните с него.** Ставит плагин для Navisworks 2024–2027 и подключает к нему AI-программы. Права администратора не нужны. |
| `NavisHelper-2.17.0.0.mcpb` | Только пользователям **Claude Desktop**, если EXE не ставили: Claude Desktop → **Settings → Extensions**, установка из файла. Тот же файл EXE кладёт под именем `NavisHelper.mcpb` в папку, которую открывает ярлык «Расширение NavisHelper для Claude Desktop». |
| `NavisHelper-full-win-x64-framework-dependent-2.17.0.0.zip` | Для установки без EXE: вручную или AI-агентом, скриптом `Install-NavisHelperBundle.ps1` из архива. |
| `SHA256SUMS.txt`, `release-receipt.json` | Для проверки, что файлы не повреждены. В `release-receipt.json` указан коммит, из которого они собраны, и хэши DLL плагина. Обычной установке не нужны. |

Перед установкой закройте Navisworks. Нужен .NET 9 Runtime: если его нет, установщик предложит открыть страницу загрузки Microsoft.

## Что нового

Все три изменения пришли из работы с настоящей моделью: RVM из E3D, сотни корней, тысячи выбранных элементов.

### Выделение ([#357](https://github.com/mikhalchankasm/NavisWorksMaster/issues/357))

- **`select_items` с `clear=true`** снимает текущее выделение. Раньше снять его было нечем: вызов с пустым списком возвращал ошибку, а подсветка выделения перекрывала цвета на снимках вида. Пустой вызов по-прежнему ошибка, но теперь она подсказывает `clear=true`.
- **`hide_selected` сохраняет выделение**, как уже делали `hide_unselected` и `unhide_selected`. Поэтому `unhide_selected` сразу после скрытия возвращает элементы, а не падает с `no_selection`.
- **`capture_current_view` с `hideSelectionHighlight=true`** снимает выделение на время снимка и возвращает его после.

### Пути к узлам RVM ([#358](https://github.com/mikhalchankasm/NavisWorksMaster/issues/358))

Это касается `parentPath` в `list_item_children` и `scopeNodePath` в `find_items`.
- Путь, записанный через `/`, находит узлы, чьи имена начинаются с `/`. Так обычно называет узлы E3D, например `/SITE-A`. Раньше такой путь не находил ничего.
- `X.rvm` теперь даёт только корень с этим именем. Раньше под него подходил ещё и дочерний узел `/X`, потому что у него тот же исходный файл, и поиск отказывал из-за двух совпадений. Совпадение по имени теперь важнее совпадения по файлу.
- Ошибка «должен найтись ровно один узел» подсказывает два пути, которые работают всегда: `parentMatchHandle` и путь в том виде, в каком его печатают инструменты (через ` / `).

### Большие ответы по страницам ([#359](https://github.com/mikhalchankasm/NavisWorksMaster/issues/359))

- **`selected_items_tree` с `offset`.** На больших выборках с габаритами ответ обрывался по времени на 1,5–2,7 тыс. элементов, а остаток получить было нельзя. Теперь ответ содержит `nextOffset`: следующий вызов с `offset=nextOffset` продолжает с того места, ничего не пропуская и не повторяя.
- **`active_model_context` с `rootItemsFormat="names"`** отдаёт только имена корней (`rootItemNames`). При 300 корнях полный ответ превышал 80 КБ, в таком виде он во много раз меньше. По умолчанию ответ прежний.

## Как обновиться

1. Закройте Navisworks и AI-программы (Claude Code, Codex, Cursor и другие).
2. Установите одним из способов:
   - **EXE:** запустите `NavisHelperSetup-2.17.0.0.exe` и оставьте флажок подключения AI-программ включённым;
   - **ZIP:** распакуйте архив и выполните `powershell -ExecutionPolicy Bypass -File .\Install-NavisHelperBundle.ps1 -ConfigureMcp`.
3. Запустите AI-программы и попросите агента вызвать `mcp_diagnostics`: он должен показать `mcpServerVersion: 2.17.0.0`. Если видна `2.16.0.0`, программа запустила старый сервер: закройте её полностью и запустите снова.
4. **Claude Desktop:** поставьте новое расширение через **Settings → Extensions** и перезапустите Desktop. Файл расширения — `NavisHelper.mcpb` из папки, которую открывает ярлык «Расширение NavisHelper для Claude Desktop», или скачанный `NavisHelper-2.17.0.0.mcpb`. Без этого шага Desktop останется на прежней версии.
   - Если в **Settings → Developer** осталась запись NavisHelper, запустите после установки расширения ярлык **«Подключить NavisHelper к AI-программам»** ещё раз: старая запись убирается, только когда расширение уже установлено.

Прежний сервер остаётся в хранилище версий `%LOCALAPPDATA%\NavisHelper\versions`. Вернуться к нему можно в PowerShell:

```powershell
& "$env:LOCALAPPDATA\NavisHelper\McpConfigurator\NavisHelper.McpConfigurator.exe" --rollback-server
```

Затем перезапустите AI-программы. Откатывается только MCP-сервер: плагин Navisworks остаётся 2.17.0.0, а `mcp_health_check` сообщает о расхождении версий (статус `degraded`). Claude Desktop эта команда не откатывает: у расширения своя копия сервера.

## Что проверено

- **Сборка:** под Navisworks 2024, 2025, 2026 и 2027; полный набор тестов (3038); CI.
- **Приёмка кандидата вживую, Navisworks 2027, 23 октября 2026**, на демо-модели из 24 объектов в трёх слоях. Установщик в тихом режиме обновил рабочую установку 2.16, `mcp_health_check` вернул `ok` с сервером и плагином 2.17.0.0. Все 10 проверок прошли:
  - `select_items` с `clear=true` снял выделение; пустой вызов вернул ошибку с подсказкой `clear=true`.
  - Снимок с `hideSelectionHighlight=true` при 8 выбранных воздуховодах по пикселям совпал со снимком без выделения. Обычный снимок отличается. Выделение после снимка осталось (8).
  - После `hide_selected` выделение сохранилось (8), и следующий `unhide_selected` вернул скрытое без ошибки.
  - `selected_items_tree` с габаритами по 5 элементов прочитал все 24 выбранных элемента за 5 страниц через `nextOffset`, без пропусков и повторов.
  - `active_model_context` с `rootItemsFormat="names"` вернул 4 имени корней и пустой полный список; неизвестный формат отклонён.
  - Путь через `/` в `list_item_children` нашёл слой HVAC с 8 потомками; `scopeNodePath` с именем корня дал ровно один узел.
- **Установщик:** прошёл сценарии сборки (чистая установка, обновление со старым сервером, обновление при занятом старом сервере, удаление), сервер отдаёт 118 инструментов. При первой сборке сценарий «занятый старый сервер» один раз упал: Windows не сразу отпустила папку новой версии. Повторная сборка из того же коммита прошла.
- **Только сборкой:** версии 2024–2026, без живого прогона.
- **Не проверено вживую:** путь к узлу, чьё имя начинается с `/`. В демо-модели таких имён нет; правило покрыто тестами. Также не проверены страницы мастера установщика в обычном режиме и установка расширения 2.17 в Claude Desktop.

## Ограничения

- AI worker и MCP-сервер, в том числе в `.mcpb`, требуют .NET 9 Runtime.
- Установщик не подписан. Windows может показать окно «Система Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае».
- Autodesk Interop берётся из установленного Navisworks.
- `selection_color_by_property` меняет постоянные цвета, которые `model_color_scheme reset` не отменяет.
- `appearance_profile_apply` применяет профиль встроенным загрузчиком Navisworks: отменяется одним Ctrl+Z, но не командой `model_color_scheme reset`. Всё, что не попало ни под одно правило, затеняется, как в самом профайлере.
- Схема `model_color_scheme` живёт, пока открыт документ в этом сеансе Navisworks: после перезапуска `reset` уже недоступен.
- Зоны коллизий строятся по точкам коллизий, а не по габаритам элементов. Сфера показывает место проблемы, а не весь пересекающийся объект.
- Выбор файла `zones.ifc` в дереве модели и поиск зон по свойству `ZoneId` работают средствами Navisworks. Отдельного окна для зон в панели NavisHelper нет.
- `clash_zones_export` анализирует не больше 50 000 результатов за прогон. При превышении он сообщает об этом и работает с первыми 50 000.
