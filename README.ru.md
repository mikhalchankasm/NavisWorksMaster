# NavisHelper

**Русский** | [English](README.md)

Плагин для Navisworks Manage и локальный MCP-сервер для инженеров-проектировщиков и BIM-координаторов, которым нужны поиск в модели, выделение, управление видимостью, точки обзора, экспорт свойств и работа с Clash Detective.

## Что делает

- Находит элементы модели по имени, условиям свойств, исходному файлу, иерархии или глобальной зоне ограничивающего параллелепипеда, затем выделяет совпадения.
- Показывает, скрывает, изолирует, кадрирует и окрашивает элементы модели с предварительным просмотром и подтверждением операций записи.
- Создаёт и изменяет наборы выделения, поисковые наборы, сохранённые точки обзора, точки обзора с секущим параллелепипедом и поддерживаемую разметку.
- Экспортирует свойства выделения и длинные списки имён из поддеревьев модели в CSV, XLSX или JSONL.
- Показывает, группирует, запускает, переименовывает, изолирует и формирует отчёты по тестам и результатам Clash Detective.
- Сохраняет проверенные многошаговые MCP-процессы как повторно используемые сценарии и преобразует их обратно в обычные вызовы инструментов.

## Примеры запросов

- «Найди все элементы, имя которых содержит `pump`, выдели совпадения и приблизь их в активном виде». (`find_items`, `select_items`, `zoom_to_selection`)
- «Покажи только непосредственных детей `/100000-XXX1-YY-01`; не сканируй более глубокие уровни». (`list_item_children`)
- «Экспортируй свойства текущего выделения в `D:\Exports\selection.xlsx`; сначала покажи предварительный план». (`selection_export_properties`)
- «Создай сохранённую точку обзора с именем `Pump room review` из текущего вида». (`create_viewpoint`)
- «Покажи активные коллизии в тесте `HVAC vs Structure`, затем изолируй первый результат». (`clash_list_results`, `clash_isolate_result`; требуются существующие результаты Clash Detective)
- «Покажи предварительную цветовую схему: элементы `_PI.rvm` — синие, `_EL.rvm` — жёлтые; перед применением дождись подтверждения». (`model_color_scheme`)
- «Сохрани текущее выделение как статический набор с именем `Review scope`». (`create_selection_set`)

## Установка

Основной способ установки — per-user installer, приложенный к GitHub Release. Он устанавливает bundle Navisworks, MCP-сервер и конфигуратор без прав администратора, затем предлагает настроить поддерживаемые MCP-клиенты.

1. Запросите последний GitHub Release.

   ```powershell
   $release = Invoke-RestMethod -Uri "https://api.github.com/repos/mikhalchankasm/NavisWorksMaster/releases/latest"
   ```

2. Скачайте установщик.

   ```powershell
   $asset = $release.assets | Where-Object { $_.name -like "NavisHelperSetup-*.exe" } | Select-Object -First 1
   if (-not $asset) { throw "NavisHelper installer asset was not found in the latest release." }
   $installer = Join-Path $env:TEMP $asset.name
   Invoke-WebRequest -Uri $asset.browser_download_url -OutFile $installer
   ```

3. Убедитесь, что Navisworks закрыт.

   ```powershell
   if (Get-Process -Name Roamer -ErrorAction SilentlyContinue) { throw "Close Navisworks before installation." }
   ```

4. Запустите установщик.

   ```powershell
   Start-Process -FilePath $installer -Wait
   ```

5. При необходимости проверьте обнаружение клиентов после их настройки установщиком.

   ```powershell
   & "$env:LOCALAPPDATA\NavisHelper\McpConfigurator\NavisHelper.McpConfigurator.exe" --detect --mcp-server "$env:LOCALAPPDATA\NavisHelper\McpServer\NavisHelper.McpServer.exe"
   ```

6. Запустите установленную версию Navisworks Manage.

   ```powershell
   $navisworksVersion = "2027"
   Start-Process "$env:ProgramFiles\Autodesk\Navisworks Manage $navisworksVersion\Roamer.exe"
   ```

## Конфигурация

Установщик автоматически настраивает поддерживаемые клиенты. Ручная запись нужна только при установке без установщика или настройке другого MCP-клиента на основе JSON.

```json
{
  "mcpServers": {
    "navishelper": {
      "command": "<path-to-install>\\NavisHelper.McpServer.exe",
      "args": []
    }
  }
}
```

Это конфигурация локального stdio-сервера. Не добавляйте host, URL или port. Сервер обнаруживает запущенные хосты плагина Navisworks и подключается через локальный именованный канал `navishelper-mcp-<PID>`.

## Статус и ограничения

- Поддерживается Navisworks Manage; bundle не объявляет поддержку Navisworks Simulate.
- Для большинства инструментов требуется запущенный хост плагина Navisworks. Для операций с моделью дополнительно нужен активный документ, а для операций с видом — активный вид.
- Работа с Autodesk API выполняется в UI-потоке Navisworks. Параллельные вызовы к одному хосту могут вернуть `host_busy`; ручная интерактивная работа NavisHelper может вернуть `interactive_busy`.
- Тайм-аут моста по умолчанию — 60 секунд плюс транспортный запас 5 секунд. Один frame именованного канала ограничен 4 MiB; для больших процессов используются paging, компактные ответы, экспорт в файлы или порционные задания.
- При нескольких окнах Navisworks используйте `instanceId` или версию Navisworks, однозначно выбирающую один хост. Match handles и ID элементов дерева действуют только в текущей сессии хоста, документа и дерева.
- `find_items_by_bbox` использует axis-aligned bounding boxes в глобальных координатах документа и единицах активной модели. Преобразование локальных или сеточных координат не выполняется.
- Сохранённые поисковые наборы Navisworks поддерживают более узкий набор условий, чем временный `find_items`. В native-условиях нет скобок, а AND имеет более высокий приоритет, чем OR.
- `saved_viewpoints_import` восстанавливает камеры, папки и простую разметку линиями/эллипсами. Другие типы разметки, clip planes, hide overrides и material overrides возвращаются как предупреждения, а не восстанавливаются.
- Для clash-инструментов требуются API Clash Detective из Navisworks Manage и существующие тесты или результаты в активном документе. Native-выполнение clash-тестов синхронное; отмена выполняется кооперативно.
- Создание скриншотов работает в режиме best-effort и зависит от плагина экспорта изображений Navisworks.
- Сборка плагина ссылается на сборки Autodesk SDK по стандартным путям `C:\Program Files\Autodesk\Navisworks Manage 20XX\`. Обычные `Debug` и `Release` ориентированы на Navisworks 2026; для релиза под четыре версии нужны `Release2024`–`Release2027`.
- В конфигурации проектов 2026/2027 остаются прямые ссылки на DevExpress 25.1, хотя связанные UI-imports закомментированы. Не установлено, нужны ли эти ссылки для публичной сборки. <!-- TODO: уточнить -->
- GitHub-hosted CI не может собрать полную матрицу Navisworks из-за отсутствия сборок Autodesk SDK на hosted runners; полная матрица и installer собираются локально.
- В репозитории нет публичной обезличенной тестовой модели Navisworks. Для live smoke testing нужна тестовая модель пользователя. <!-- TODO: уточнить -->
